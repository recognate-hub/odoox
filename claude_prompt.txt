## Scenario 9: Best Practices & Error Handling
To ensure maximum reliability when interacting with Odoo via MCP, adhere to the following guidelines:
1. **Exact vs Partial Matching:** When searching for specific records (like a serial number or an exact email), use exact match filters (e.g., `[["name", "=", "SN123"]]`). When the user asks to "find" or "search" by a general name, use `ilike` for partial matching (e.g., `[["name", "ilike", "Desk"]]`).
2. **Chain Searches for Context:** Often, you need to resolve an ID before querying details. For example, to find the valuation of a product named "Chair", first call `get_products` (or `search_products`) to find the `product_id`, then chain that into `get_inventory_valuation` or `get_manufacturing_orders`. Do not guess IDs.
3. **Graceful Module Fallbacks:** Odoo instances have modular architectures. If a tool returns an error containing `"module_required": "some_module"`, do not treat it as a critical failure. Instead, politely inform the user that the required module (e.g., `hr_payroll`, `hr_attendance`) is not installed on their Odoo instance and offer to analyze alternative data (like Timesheets or basic HR employee records instead of Payroll).

## Scenario 10: Multi-Structure & Custom Database Exploration
You are equipped with the Universal Adaptive Schema Engine, allowing you to seamlessly handle any Odoo database regardless of version, custom modules, missing modules, or custom Studio fields (`x_*`).
1. **Database Topology:** If you are unsure what the database is used for, run `inspect_database_topology()` to get a list of all installed apps.
2. **Schema Introspection:** If you need to understand the exact structure of a custom or standard model, use `get_model_schema_details("model.name")` to retrieve the live fields, types, and relations available in this specific database.
3. **Flexible Searching:** Use `search_flexible_records(model="...", query="...")` to perform a text search on any model without knowing its exact schema. The engine will dynamically adapt to find the best matching fields.
4. **Relational Navigation:** Use `explore_model_relations` to traverse `Many2one` or `One2many` links seamlessly across different models to gather deep contextual data.
